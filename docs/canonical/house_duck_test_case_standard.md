# House Duck 테스트 케이스 공통 기준

> 버전: 1.0 · 기준일: 2026-08-09  
> 원본 연구: [TC 포폴 리치 재직중](https://docs.google.com/spreadsheets/d/1QKQx_Fecv4zRmH4anjX0FpJ3nyWItv0gaNV941GFPp0/edit?usp=sharing)  
> 적용 대상: House Duck의 모든 Godot 게임  
> 유지 규칙: 프로젝트별 복사본은 바이트 단위로 동일하게 유지하고, 게임 고유 매핑은 각 프로젝트 QA 문서에만 쓴다.

## 1. 목적

이 문서는 기능이 “한 번 눌린다”는 확인을 넘어, 실제 플레이 중 생기는 상태 변경·재진입·경계값·플랫폼 차이까지 빠뜨리지 않기 위한 공통 기준이다. 원본 워크북의 76개 탭, 숫자 ID 기준 9,070개 실행 케이스와 15,355개 데이터 검증 항목을 구조와 실패 유형 중심으로 분석해 일반화했다.

다음 세 질문에 모두 답하지 못하면 테스트 완료가 아니다.

1. 어떤 상태에서 무엇을 했는가?
2. 플레이어에게 무엇이 보여지고, 저장·서버·재화에는 무엇이 남아야 하는가?
3. 같은 행동을 반복하거나 중간 종료·재접속해도 결과가 한 번만 정확히 유지되는가?

## 2. 테스트 케이스 한 줄 계약

모든 케이스는 사전조건 → 행동 → 기대결과 → 증거 순서로 읽혀야 한다.

| 필드 | 필수 내용 |
|---|---|
| TC ID | 프로젝트 접두사 + 영역 + 번호. 한번 배포한 ID는 재사용하지 않는다. |
| 분류 | BAT, BVT, Feature, Risk, Visual, Device, Data 중 하나 이상 |
| 우선순위 | P0 출시 차단, P1 핵심 회귀, P2 일반, P3 탐색 |
| 사전조건 | 계정/세이브/챕터/해금/재화/네트워크/시간/권한/언어/기기 상태 |
| 행동 | 한 케이스에서 검증할 핵심 행동 하나. 여러 화면 순회는 목적이 흐려지지 않을 때만 묶는다. |
| 기대결과 | 화면, 입력, 상태, 저장, 서버, 재화, 소리까지 관찰 가능한 결과 |
| 플랫폼 | Common, Android, iOS, Desktop QA. 플랫폼별 결과를 섞어 쓰지 않는다. |
| 자동화 | 자동/수동/혼합과 실행 명령 또는 캡처 경로 |
| 결과 | Pass, Fail, Blocked, N/A, Not Tested |
| 증거 | 빌드/커밋, 로그 SUMMARY, 캡처·영상, 서버 응답 또는 저장 스냅샷 |
| 이슈 | 재현 가능한 Fail은 이슈 ID와 연결한다. |

기대결과는 “정상 노출”처럼 모호하게 쓰지 않는다. 예: “팝업이 닫히고 이전 화면의 선택 상태가 유지되며, 뒤 UI는 한 번만 입력된다.”

## 3. 모든 기능에 적용하는 파생 케이스

기본 성공 케이스 하나를 만들었으면 아래에서 관련 있는 변형을 반드시 파생한다.

1. **부정 경로**: 조건 부족, 잠김, 취소, 실패 응답.
2. **경계값**: 0/1/최대/최대 초과, 처음/마지막 항목, 빈 목록/항목 1개.
3. **반복 입력**: 더블탭, 길게 누르기, 연타, 다중 터치, 키와 터치 동시 입력.
4. **뒤로가기**: 시스템 뒤로가기, UI 닫기, Esc, 화면 밖 탭. 모두 같은 소유권 규칙을 지킨다.
5. **재진입**: 화면을 나갔다 돌아오기, 앱 백그라운드 왕복, 강제 종료 후 재접속.
6. **상태 변경**: 화면을 연 채 재화·권한·레벨·소속·서버 데이터가 달라지는 경우.
7. **플랫폼 차이**: 안전영역, 홈바/노치, 기기 키보드, 권한 회수, 화면 회전 금지.
8. **긴 현지화**: 독일어 장문, 아랍어 RTL, 큰 글자, 숫자 자릿수 증가.
9. **느린 환경**: 지연, 타임아웃, 오프라인, 재시도, 중복 콜백, 콜백 없음.
10. **업데이트 경계**: 이전 버전 세이브·미완료 콘텐츠·누락 리소스·건너뛴 버전.

## 4. 공통 위험 영역

### 4.1 앱 생명주기와 진입

- 완전 신규, 기존 세이브, 손상 세이브, 이전 버전 세이브로 각각 시작한다.
- 스플래시·로딩·동의·로그인·세이브 선택은 다음 화면과 겹치거나 먼저 사라지지 않는다.
- 로딩 중 백그라운드, 네트워크 변경, 연타, 강제 종료 뒤에도 안전하게 복구한다.
- 업데이트 필수/선택, 점검, 화이트리스트, 데이터 패치 실패를 구분한다.
- 첫 프레임 오류, 크래시, ANR, 무한 로딩, 소리 끊김을 별도 기록한다.

### 4.2 이동·뒤로가기·레이어

- 모든 화면은 진입 경로와 탈출 경로가 있다. 튜토리얼 잠금은 의도된 경로만 허용한다.
- 팝업·도움말·토스트·튜토리얼·광고·기기 키보드의 z 순서를 검증한다.
- 상위 레이어가 열리면 뒤 UI 입력·스크롤·물리·타이머가 계약대로 차단된다.
- 닫기는 현재 최상위 레이어 하나만 닫고 엉뚱한 화면으로 이동하지 않는다.
- 화면 전환 중 입력은 무시되거나 한 번만 큐잉되며 중복 씬을 만들지 않는다.
- 하단 내비게이션과 공통 HUD는 유지 대상 화면에서 사라지거나 중복되지 않는다.

### 4.3 입력·조작

- 최소 터치 영역, 한 손 도달 범위, 조이스틱 데드존, 8방향 키를 각각 확인한다.
- 충돌·가속·제동·회전은 보이는 모델과 물리 위치가 일치한다.
- 버튼 비활성은 색만 흐려지는 것이 아니라 실제 입력도 막는다.
- 드래그·핀치·스크롤 끝단·러버밴드가 부모 버튼 탭과 충돌하지 않는다.
- 조작 도중 팝업, 앱 중단, 결과 전환이 발생해도 입력 상태가 붙잡혀 남지 않는다.

### 4.4 화면·에셋·오디오

- 대표 세로 해상도, 최소/최대 지원 비율, 안전영역에서 잘림·겹침·빈 틈을 본다.
- 주제/부주제/행동의 시각 강약, 포트레이트 시선, 레이어, 하단 페이드, 배경 밀도를 확인한다.
- 임시 도형·더미·깨진 알파·흰 테두리·누락 아이콘은 출시 차단 항목이다.
- 동일 역할 컴포넌트의 높이·여백·모서리·폰트·버튼 상태는 공통 토큰과 일치한다.
- 소리 ON/OFF, 슬라이더, BGM 전환, 화자별 타이핑음, 앱 중단/복귀를 검증한다.
- 시각 QA는 정지 캡처뿐 아니라 진입·전환·종료 중간 프레임도 본다.

### 4.5 저장·시간·복구

- 성공 결과는 한 번만 저장되고 취소·실패·QA 모드는 라이브 세이브를 바꾸지 않는다.
- 저장 중 종료, 임시파일만 존재, 손상 JSON, 디스크 쓰기 실패를 복구한다.
- 대사·튜토리얼·미니게임 중단 지점을 안정 ID로 재개한다.
- 서버 시간과 기기 시간 조작, 일일 초기화, 쿨다운, 백그라운드 경과를 구분한다.
- 레벨·구매·권한 변경 뒤 최대치와 남은 횟수가 화면 재진입 시 즉시 갱신된다.
- 마이그레이션은 한 버전씩 건너뛰지 않고 최신까지 연속 적용하며 원본 백업을 보존한다.

### 4.6 계정·네트워크·권한

- 로그인 만료, 다른 기기 접속, 로그아웃, 탈퇴, 재연결을 구분한다.
- 요청 성공/명시 실패/타임아웃/콜백 없음/늦은 콜백을 각각 처리한다.
- 재시도와 연타는 같은 보상·구매·가입을 중복 생성하지 않는다.
- 화면을 연 상태에서 권한이나 소속이 바뀌면 즉시 갱신하거나 안전하게 재조회한다.
- 서버 빈 값이 유효한 로컬 신원을 덮어쓰지 않는다.
- 민감 작업은 실제 서버 응답과 권한 정책까지 확인하며 클라이언트 로그만으로 통과시키지 않는다.

### 4.7 경제·보상·광고·결제

- 지급 전/후 재화와 아이템 차이를 확인하고, 실패·취소·재접속에서도 정확히 한 번만 반영한다.
- 무료/유료/광고 대체 경로의 게임 결과는 계약상 동일해야 한다.
- 보상형 광고는 시청 완료 콜백에서만 지급하고 중도 닫기에는 지급하지 않는다.
- 전면 광고 중 입력·물리·타이머·BGM 정지를 확인한다.
- 구매 복원, 영수증 실패, 환불·권리 회수, 이미 보유한 영구 상품을 확인한다.
- 빨간점/보상 합계는 일부가 아니라 모든 수령 가능 항목이 사라졌을 때만 꺼진다.

### 4.8 콘텐츠·해금·목록

- 0개일 때 숨김, 1개일 때 등장, 최대 개수, 정렬, 필터, 페이지 끝을 확인한다.
- 잠김과 선택 불가를 구분하고 해금 조건·안내 문구·딥링크 목적지가 일치해야 한다.
- 콘텐츠를 건너뛴 업데이트 사용자도 다음 안정 ID로 이어진다.
- 기록/도감/스토리 다시보기는 진행 저장을 바꾸지 않고 이미 본 연출을 안전하게 재생한다.
- 누락 아이콘·삭제된 데이터·알 수 없는 ID는 크래시 대신 정의된 fallback을 사용한다.

## 5. 스위트 계층

| 스위트 | 실행 시점 | 최소 범위 |
|---|---|---|
| BAT | 모든 후보 빌드 | 기동, 로그인/세이브, 핵심 루프 1회, 종료 |
| BVT | 기능 통합·배포 후보 | 모든 주요 화면 진입, 핵심 행동 1회, 설정, 업데이트/점검 |
| Feature | 기능 작업 중 | 해당 요구사항의 성공·실패·경계·재진입 |
| Risk | 저장/경제/서버/광고/결제 변경 | 중복·유실·권한·오프라인·마이그레이션 |
| Visual | UI/에셋/연출 변경 | 기준 해상도, 긴 언어, 중간 프레임, 전후 캡처 |
| Device | 출시 전 | 실제 Android/iOS 입력, 안전영역, 성능, 네이티브 SDK |
| Data | 콘텐츠/밸런스 갱신 | ID, 참조, 타입, 범위, 중복, 누락, 집계 일치 |

헤드리스 PASS는 Device·Visual·광고·결제·실서버를 증명하지 않는다.

## 6. 실행 게이트

- **작업 시작 전**: 변경 영역의 기존 TC와 최근 Fail/Blocked를 읽는다.
- **구현 전**: 재현 가능한 버그는 먼저 실패 케이스로 고정한다.
- **로컬 완료 전**: Feature + 관련 Risk + 파싱 검사를 실행한다.
- **화면 변경 완료 전**: Visual 캡처를 실제 진입 경로에서 확인한다.
- **마일스톤 전**: BAT + BVT + 핵심 루프 자동주행 + 데이터 검사를 한 바퀴 돈다.
- **릴리스 전**: 위 전부와 Device, 광고/결제/서버 샌드박스, 크래시/성능을 통과한다.
- **작업 종료**: 에이전트가 띄운 엔진·게임·MCP·디버그 프로세스를 종료하고 잔존 여부를 보고한다.

P0/P1 Fail, 결과 없는 P0, 근거 없는 Pass, 최신 빌드와 맞지 않는 증거가 하나라도 있으면 후보 빌드를 통과시키지 않는다. Blocked는 통과가 아니며 차단 사유와 해제 조건이 있어야 한다.

## 7. 결과와 증거 규칙

- **Pass**: 해당 빌드에서 기대결과 전체를 관찰했고 증거가 있다.
- **Fail**: 기대결과 하나라도 다르며 재현 정보가 있다.
- **Blocked**: 환경·계정·서버·기기 때문에 실행하지 못했다.
- **N/A**: 제품 계약상 적용되지 않으며 이유가 있다.
- **Not Tested**: 아직 실행하지 않았다.

대시보드 합계는 원본 행 합계와 자동 대조한다. 새 시트·기능이 집계에서 빠지거나 수식 범위가 오래되면 테스트 자체가 녹색이어도 QA 현황은 신뢰하지 않는다. 플랫폼별 결과 열이 여러 개면 “케이스 수”와 “실행 결과 수”를 별도로 센다.

## 8. 자동화와 수동 검수의 경계

자동화하기 좋은 것:

- 파싱, ID/경로/데이터 참조, 저장 마이그레이션, 상태 전이, 중복 지급, 잠금 조건.
- 모든 주요 화면의 진입·뒤로가기·팝업 소유권.
- 고정 시드 루프, 경계값, 결과 스냅샷, 캡처 해상도.

사람이 반드시 볼 것:

- 재미, 맥락, 다음 목표의 명확성, 조작감, 웅장함과 보상감.
- 포트레이트 얼굴/시선/레이어, 배경 밀도, 버튼 강약, 전환 템포.
- 실제 스피커·이어폰 오디오, 진동, 실제 광고·결제·권한 UI.
- 저사양 기기 성능과 발열, 손가락 가림, 노치·홈바.

## 9. 재발 방지

- 같은 결함이 두 번 나오면 개별 화면 패치로 끝내지 않고 공통 컴포넌트·상태 소유자·QA 계약 중 한 곳에서 막는다.
- 버그 수정은 원인과 가장 가까운 공용 지점을 고치고 형제 호출 경로를 함께 실행한다.
- TC ID는 이슈, 요구사항, 자동 테스트 이름과 추적 가능하게 연결한다.
- 오래된 Pass는 코드·데이터·엔진·SDK·플랫폼 중 관련 항목이 바뀌면 만료한다.
- 원본 워크북의 제품 고유 문구와 데이터는 복사하지 않는다. 이 문서의 구조와 위험 기준만 재사용한다.
