# Quirky Tower 통합 층 도전 설계

## 목표

분리된 미니게임을 차례로 보여주는 현재 플레이를 하나의 짧은 층 돌파로 교체한다. 매 층에서 사용자는 위험 경로를 고르고, 캐릭터를 직접 움직여 장애물을 피하고, 마지막 순간에 타이밍 입력으로 문을 파괴한다. 선택·직접 조작·순간 판정이 모두 한 점수와 콤보로 이어져야 한다.

## 첫 30초

```text
1층 경로 선택
  -> 3초 직접 회피
  -> 타이밍 파괴
  -> PERFECT/GREAT/FAIL 연출
  -> 점수·콤보·하트 반영
  -> 즉시 다음 층
```

설명 화면을 먼저 띄우지 않는다. 경로 버튼의 짧은 이름과 보상 배수, `드래그`, `지금 탭` 문구만으로 조작을 전달한다. 한 층은 결과 확인을 포함해 약 6초를 목표로 한다.

## 세 가지 재미의 연결

### 1. 전략 선택

층 시작 시 세 경로 중 하나를 고른다.

| 경로 | 위험 | 판정 | 점수 |
|---|---:|---:|---:|
| 안전로 | 낮음 | 넓음 | ×1.00 |
| 위험로 | 보통 | 기본 | ×1.25 |
| 방송사고 | 높음 | 좁음 | ×1.50 |

경로 선택은 별도 메뉴가 아니라 현재 층 위에 바로 표시한다. 높은 배수는 장애물 수와 속도, 마지막 판정 폭을 함께 어렵게 만든다.

### 2. 직접 조작

사용자는 화면 아래의 참가자를 좌우로 드래그한다. 장애물은 위에서 내려오며, 충돌하면 즉시 실패시키지 않고 회피 점수를 낮춰 마지막 파괴에서 만회할 기회를 남긴다. 같은 장애물의 연속 충돌은 짧은 무적 시간으로 막는다.

### 3. 순간 판정과 카타르시스

회피가 끝나면 문과 왕복 바늘이 나타난다. 화면을 탭하면 문을 가격한다. 회피 성적과 타이밍 정확도를 합쳐 기존 `ChallengeRules`가 이해하는 입력값으로 변환한다.

- `PERFECT`: 중앙에 매우 근접. 큰 화면 플래시와 파편, 콤보 강조.
- `GREAT`: 성공 범위 안. 작은 파편과 점수 강조.
- `MISS`: 실패 범위. 하트 손실과 빠른 같은 층 재도전.

결과 연출은 약 0.55초 뒤 기존 결과 오버레이로 연결한다. 장시간 정지나 별도 보상 화면은 만들지 않는다.

## 기존 15층 구조와의 연결

- 15층, 하트, 콤보, 체크포인트, 스토리, Quirk, Sponsor Boost 규칙은 유지한다.
- 기존 `timing_ring`, `tap_panic`, `drag_dodge` ID는 헤드리스 밸런스와 층별 성향을 위해 유지한다.
- 화면에서는 세 ID 모두 같은 통합 도전 씬을 사용한다.
- ID는 최종 판정 변환 방식과 방송 문구를 바꿔 층의 성격을 남긴다.
- 4·8·12층 Quirk 선택과 5·10·15층 스토리 오버레이는 현재 흐름을 재사용한다.

## Quirk의 눈에 보이는 효과

- `wide_window`: 마지막 파괴 성공 구간이 실제로 넓어진다.
- `overheat_combo`: 고배수 문구와 점수는 커지지만 실패 시 하트 손실이 증가한다.
- `replay`: 첫 실패 후 하트 손실 없이 같은 층에 재도전한다.
- `reroute`: 층의 판정 성향과 방송 문구가 다음 유형으로 바뀐다.

새 Quirk는 추가하지 않는다. 기존 네 개가 통합 루프에서 체감되는지 먼저 확인한다.

## 스토리와 플러스알파

플레이 중 한 줄짜리 방송 자막을 사용한다. 안전로는 진행자의 정상 멘트, 위험로는 과장된 응원, 방송사고 경로는 방송국의 모순이나 숨겨진 문구를 보여준다. 5·10·15층의 기존 스토리 이벤트는 긴 컷신 대신 이 자막의 의미를 뒤집는 짧은 결과로 유지한다.

`방송 열기` 표시는 콤보와 위험 경로에 따라 올라간다. 이번 프로토타입에서는 시각 피드백만 제공하며 별도 저장값이나 보상 재화는 만들지 않는다.

## BM 연결 범위

현재 Sponsor Boost의 광고·결제 동등성 규칙은 바꾸지 않는다. 프로토타입에는 실제 광고·결제를 연결하지 않는다. 이후 Boost UI가 붙을 때는 하트 보호, 판정 폭 확대, 추가 Quirk 선택 중 하나를 동일 한도와 동일 효과로 제공한다. 정상 Boost 사용자를 랭킹에서 분리하지 않는다.

## 아키텍처

- 새 `tower_trial.tscn`과 `tower_trial.gd`가 경로 선택, 회피, 파괴, 짧은 연출을 소유한다.
- `RunController`는 모든 기존 도전 ID를 이 씬으로 연결하고 `difficulty`, Quirk modifier, challenge ID를 전달한다.
- 도전 씬은 `finished(input_value, score_multiplier)` 신호만 내보낸다.
- `RunEngine.resolve_floor`는 기본값이 `1.0`인 점수 배수를 받아 성공 점수에만 적용한다. 헤드리스 시뮬레이션은 기존 호출을 그대로 사용한다.
- 공통 색과 여백은 기존 `AppTheme.tres`와 `DesignTokens`만 사용한다.

## 오류와 입력 잠금

- 경로를 고르기 전 드래그와 탭은 무시한다.
- 회피 중에는 좌우 이동만 받고, 파괴 단계에서는 첫 탭만 받는다.
- 결과를 보낸 뒤 모든 입력을 잠근다.
- 도전 씬 교체와 버튼 제거는 `queue_free`를 사용해 신호 처리 중 locked object 크래시를 피한다.
- 알 수 없는 challenge ID는 안전하게 `timing_ring` 성향으로 처리하지 않고 기존 core 오류로 드러낸다.

## 검증 기준

- 경로 선택 후 회피, 파괴, 결과 신호까지 한 씬에서 진행된다.
- 안전로보다 방송사고 경로의 장애물과 점수 배수가 크다.
- 성공 결과 배수가 실제 런 점수에 반영되고 실패 점수는 0이다.
- 실제 Godot 입력으로 경로 버튼, 드래그, 파괴 탭, 결과 버튼, 다음 층 진입을 관찰한다.
- 기존 헤드리스 테스트, 고정 시드 스모크, 10,000런 밸런스 결과가 유지된다.
- macOS 검증을 Android/iOS 실제 손가락 검증으로 과장하지 않는다.

## 이번 범위에서 제외

- 최종 캐릭터·배경 아트와 오디오·햅틱
- 실제 광고·결제·Supabase·온라인 랭킹
- 새로운 Quirk, 재화, 홈 화면, 튜토리얼 페이지
- 기존 세 독립 도전 씬 삭제

이 항목은 통합 루프를 사람이 직접 플레이해 재미와 조작 문제가 확인된 뒤 결정한다.
