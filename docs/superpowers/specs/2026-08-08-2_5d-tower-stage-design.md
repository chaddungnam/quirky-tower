# Quirky Tower 2.5D 무대 디자인

## 목표

현재의 `경로 선택 → 3초 회피 → 문 파괴` 한 층 루프를 규칙 변경 없이 Godot 기본 3D 무대로 교체한다. 플레이어는 고정 사선 카메라 아래에서 멀리 보이는 장애물의 깊이를 읽고 좌우로 피한 뒤, 문 앞 타이밍을 맞춰 즉시 파괴한다.

## 참조 해석

- 영상과 스크린샷의 우주 배경은 복제하지 않는다.
- 가져올 요소는 작은 픽셀 캐릭터 루프, 선택 시 발광, 역할별 강조색, 즉각 바뀌는 상태 피드백이다.
- 장비·스탯·덱 시스템은 이번 핵심 재미와 무관하므로 만들지 않는다.
- 기존 Quirky Ball의 크림·코랄 중심 색 대신 먹색 밤, 라임 방송등, 복숭아 경고, 연보라 비밀신호를 사용한다.

## 플레이 경험

1. 세 경로는 세로 버튼으로 유지한다. 안전로는 라임, 위험로는 복숭아, 방송사고는 연보라로 구분한다.
2. 선택 즉시 카메라 앞 픽셀 진행자가 해당 색으로 반응하고 장애물이 복도 끝에서 다가온다.
3. 장애물은 화면 Y 좌표로 흘러오는 도형이 아니라 `Area3D`와 실제 깊이를 가진 저폴리 방송 차단봉이다.
4. 플레이어는 `CharacterBody3D`와 실제 콜라이더로 좌우 이동한다. 가까워질수록 장애물이 커지므로 충돌 시점을 미리 읽을 수 있다.
5. 회피가 끝나면 멀리 보이던 출구가 전면으로 강조되고, 기존 타이밍 바를 탭해 문을 부순다.
6. 성공 품질에 따라 문이 벌어지고 캐릭터가 튀며 기존 점수 입력과 배수로 돌아간다.

## 기술 구조

- `TowerTrial`은 단계, 문구, 결과 계산과 2D HUD만 소유한다.
- `TowerStage3D`는 카메라, 저폴리 지오메트리, 픽셀 표면, 플레이어 이동, 장애물 이동과 충돌만 소유한다.
- 두 노드는 `player_hit` 신호와 `configure/start_dodge/set_player_axis/show_smash/show_feedback` 호출로만 연결한다.
- 무대는 `SubViewportContainer` 안에 렌더링하여 기존 세로 UI와 입력 체계를 유지한다.
- 외부 에셋, 셰이더, 3D 플러그인 없이 `BoxMesh`, `StandardMaterial3D`, `ImageTexture`, `Sprite3D`, `StaticBody3D`, `CharacterBody3D`, `Area3D`만 사용한다.
- 바닥 픽셀 표면과 캐릭터는 작은 `Image`를 코드에서 한 번 생성하고 nearest 필터로 표시한다.

## 공통 규칙

- 헤드리스 `RunEngine`과 15층 데이터는 변경하지 않는다.
- 다중 선택은 외국어 길이 대응을 위해 계속 세로 배치한다.
- 색상은 `DesignTokens`의 의미 역할에서만 조회한다. 기존 이름은 호환 별칭으로 남긴다.
- 배경·플레이면·플레이어/상호작용 요소는 명도 차이로도 구분되어야 한다.
- Supabase, 결제, 광고, 랭킹은 이번 범위 밖이다.

## 완료 기준

- 메인 씬에서 홈을 거쳐 플레이하면 한 층의 선택, 실제 3D 회피, 문 파괴, 결과까지 진행된다.
- 자동 테스트가 고정 직교 사선 카메라, 픽셀 `Sprite3D`, 바닥 `StaticBody3D`, 장애물 `Area3D`, 실제 `body_entered` 충돌을 확인한다.
- 기존 전체 헤드리스 QA와 프로젝트 파싱이 통과한다.
- 실제 게임 캡처에서 목적지, 플레이어, 위험물이 3초 안에 구분된다.
