  • 초기값: 기본기·액티브는 ready, 대표기는 초기 CD 1. KO 유닛의 쿨다운과 상태는 동결하며 PvP 부활은 없다.

한 행동의 권위적 판정 순서
  1. 행동 시작 DoT → HP 0/KO 판정. 이 시점에 KO되어도 DOT_KO 한 행동으로 ledger와 24행동 상한에 포함하고, 해당 DoT tick만 소모한 뒤 다른 쿨다운·상태는 동결한다.
  2. 이동과 이동 중 소품 접촉을 tile ID 오름차순으로 판정.
  3. 스킬 대상 snapshot → 직접 피해/회복/보호막을 대상 ID 오름차순으로 계산.
  4. 같은 스킬의 동시 피해를 모두 적용한 뒤 동시 KO를 판정.
  5. 밀침 → 벽/유닛 충돌 → 배럴 연쇄를 최대 1회 판정. 중간에 마지막 적이 KO되어도 이미 시작한 command의 authored event를 생략하지 않는다.
  6. 상태 부여·정화 → 점수 → 쿨다운/지속 감소 → 다음 게이지 순서 갱신.
  7. 전체 RESOLVE 뒤 먼저 전멸을 판정하고, 전멸이 없을 때 24행동/시간 종료를 판정한다. 양 팀 동시 전멸이면 점수와 동점 규칙을 사용한다.

직접 피해 modifier·반올림 순서
outgoing = clamp(1 + sum(attacker outgoing modifiers), 0.50, 1.50)
exposure = clamp(1 + sum(target mark/vulnerability), 1.00, 1.50)
incoming = clamp(1 - sum(target reductions), 0.50, 1.00)

서버 도입 순서
  1. Local: battle state, seed, command ledger, bot, 결과를 한 기기에서 재현.
  2. Supabase P1: 계정, 프로필, 편성 snapshot, 단일 시즌 랭킹, match/command 원장.
  3. 시즌 비동기: server seed/state 수신 → 현재 유닛의 command 1개 제출 → 서버 검증·새 state 저장 → 상대 알림.

  6. 즉시 방어전·협동·길드: 실제 턴 교환과 원장이 안정된 뒤.

  • 원자성: 이동과 스킬/방어를 command 1개로 제출한다. 서버 승인 전 클라이언트 화면은 preview일 뿐이다.

  • 중복: command_id는 match 안에서 unique다. 같은 ID 재전송은 새 행동을 만들지 않고 저장된 동일 응답을 반환한다. client_sequence는 진단용이며 권위가 아니다.

  • 드리프트 방지: Gate F 전에 동일 JSON state/command/result golden vector 1,000개 이상을 GDScript와 TypeScript 양쪽에 실행해 state/event hash 불일치 0을 증명한다. match는 시작 rule_version에 고정한다.
